# Дополнительные спецификации Ритмо

Версия 1.0, 16.11.2026. Уточняют SDD 1.1, не расширяют выпуск V3.

## Бизнес-правила

| ID | Правило | Основание |
|---|---|---|
| BR-01 | Только владелец может читать и изменять свои данные; ID владельца берётся из сессии. Чужой ID даёт 404. | REQ-SEC-001; SYS-01 |
| BR-02 | Для изменений нужны действующая сессия и CSRF; без них 401/403. Пароли хранятся как salted adaptive hash. | REQ-FUNC-001; ADR-003 |
| BR-03 | Название после trim содержит от 1 до 80 Unicode code points; переименование сохраняет историю. | REQ-FUNC-003/004; VIEW-02 |
| BR-04 | today читается ровно один раз на запрос из Clock в Europe/Minsk. expectedDate должна совпасть, иначе 409 DAY_CHANGED без записи. | REQ-FUNC-005; SYS-03 |
| BR-05 | Пара habit_id и completion_date уникальна. PUT создаёт не более одной отметки; DELETE сегодня удаляет её, повтор не меняет результат. | REQ-FUNC-005; SYS-02 |
| BR-06 | Серия считается от сегодня, если отметка есть, иначе от вчера, до первого пропуска. Очки равны 10 × число сохранённых отметок владельца. | REQ-FUNC-006/007 |
| BR-07 | Удаление привычки после подтверждения каскадно удаляет её отметки и уменьшает производные очки. | REQ-FUNC-004; ADR-002 |
| BR-08 | CSV содержит только свои отметки существующих привычек. Диапазон включителен: 1…366 дней, без будущих дат. Пустая выгрузка содержит заголовок. | REQ-FUNC-009; CR-01 |
| BR-09 | CSV: UTF-8 с BOM, «;», date;habit;points; порядок по дате и habit_id; кавычки экранируются, потенциальные формулы нейтрализуются. | REQ-FUNC-009; AT-11 |
| BR-10 | Запись, пересчёт и удаление выполняются атомарно; блокируется Habit, используется REPEATABLE READ. При ошибке rollback, ложный успех запрещён. | SYS-02; AT-12 |
| BR-11 | Прошлые даты через публичный API неизменяемы. Смена дня меняет представление, а не удаляет историю. | REQ-FUNC-005; VIEW-04 |
| BR-12 | Значок, напоминания, социальные роли и внешние интеграции в текущую модель выпуска не входят. | ADR-004; SDD 1.1 |

## Общие требования качества

- SUP-U1: ошибки у полей и понятные сообщения, запрет ложного успеха; при DAY_CHANGED перечитать список без автоматического повтора (SYS-04, AT-13).
- SUP-R1: данные сохраняются в PostgreSQL на постоянном диске, перезапуск требует нового входа, но не уничтожает прогресс (REQ-REL-001, AT-09).
- SUP-R2: SQL-ошибка откатывает всю операцию; конкурирующие PUT и удаление синхронизируются по Habit (SYS-02, AT-12).
- SUP-S1: серверная сессия, HttpOnly, SameSite=Lax, CSRF для изменений, no-store для личных данных. Secure включается при HTTPS; локальное исключение только loopback HTTP (ADR-003).
- SUP-P1: один локальный экземпляр API, пул БД не более 5, диапазон CSV не более 366 дней. Время ответа не нормировано исходной SRS, нагрузочные измерения не проводились.
- SUP-M1: Clock внедряется для воспроизводимых проверок границы суток; исходники схем редактируемы, имена совпадают с SDD.
- SUP-C1: Java 21, React, PostgreSQL по VIEW-05 ЛР4; макет доменной логики ЛР5 не заменяет сервер, интерфейс и БД.

## Контракт CSV

UTF-8 с BOM; строки CRLF; разделитель `;`; заголовок `date;habit;points`.
Даты ISO YYYY-MM-DD, порядок по дате и habit_id. На каждую отметку points=10.
Поле habit заключается в кавычки, внутренние кавычки удваиваются.
Строка, начинающаяся после начальных пробелов/табуляции с `=`, `+`, `-`, `@`, нейтрализуется префиксом апострофа.
Диапазон включительный 1…366 дней; `from <= to <= today`.

## Единый ответ ошибки

`{code,message,fieldErrors}`. 400 — неверные данные; 401 — нет сессии;
403 — CSRF; 404 — ID отсутствует или принадлежит другому; 409 — LOGIN_EXISTS / DAY_CHANGED;
500 — непредвиденная ошибка без внутренних данных. При сбое нет успешного ответа.
