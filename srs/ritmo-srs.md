## 1. Введение

«Ритмо» — учебное веб-приложение для учёта ежедневных привычек и поддержки мотивации.

<a id="11-document-purpose"></a>

### 1.1 Назначение документа

Документ описывает пожелания условного заказчика и минимальные требования к лабораторному проекту. Он используется для разработки и демонстрации результата преподавателю.

<a id="12-product-scope"></a>

### 1.2 Область применения продукта

Заказчику нужен простой сервис, в котором пользователь записывает полезные привычки, ежедневно отмечает выполнение и видит свой прогресс. Основная ценность — наглядность регулярных действий и небольшое игровое поощрение.

| Бизнес-цель | Как продукт её поддерживает |
|---|---|
| Помочь организовать ежедневные действия | Список привычек и отметки за сегодня |
| Мотивировать продолжать | Серии дней и очки за выполнение |
| Показывать результат усилий | Счётчик серии и значок за 7 дней подряд |

Учебная версия включает регистрацию, вход, управление ежедневными привычками, отметки, серии, очки и один вид значка. Напоминания, выбор дней недели, календарь, графики, уровни, социальные функции, платежи и ИИ в объём работы не входят. Набор участников и измерение бизнес-метрик не требуются.

<a id="13-definitions-acronyms-and-abbreviations"></a>

### 1.3 Определения, акронимы и сокращения

| Термин | Значение |
|---|---|
| Привычка | Действие, которое пользователь планирует выполнять каждый день |
| Отметка | Запись о выполнении привычки за определённую дату |
| Стрик / серия | Количество последовательных дней выполнения привычки |
| Очки / XP | Игровой показатель: 10 очков за одну отметку |
| SRS | Спецификация требований к программному обеспечению |
| MVP | Минимальная версия продукта |

## 2. Обзор продукта

Продукт предназначен для самостоятельного ежедневного использования.

<a id="21-product-perspective"></a>

### 2.1 Перспектива продукта

Приложение состоит из веб-интерфейса на React, сервера на Java и базы данных. Для лабораторной достаточно запуска на компьютере разработчика; публикация в интернете не требуется.

<a id="22-product-functions"></a>

### 2.2 Функции продукта

1. Зарегистрироваться и войти.
2. Создать, переименовать или удалить привычку.
3. Отметить выполнение за сегодня или отменить отметку.
4. Увидеть текущую серию дней и общую сумму очков.
5. Получить значок за серию из 7 дней.

<a id="23-product-constraints"></a>

### 2.3 Ограничения продукта

- Серверная часть — Java, клиентская — React.
- Все привычки ежедневные; отдельного расписания нет.
- Интерфейс на русском языке, проверка в одном браузере — Chrome на компьютере.
- Единая дата для всего приложения определяется сервером в часовом поясе Europe/Minsk.
- Достаточно одного работающего экземпляра приложения и одной базы данных.

<a id="24-user-characteristics"></a>

### 2.4 Характеристики пользователей

| Роль | Возможности |
|---|---|
| Гость | Регистрация и вход |
| Пользователь | Работа со своими привычками и просмотр прогресса |

Отдельная роль администратора и административная панель не требуются.

<a id="25-assumptions-and-dependencies"></a>

### 2.5 Допущения и зависимости

Пользователь самостоятельно подтверждает выполнение действия. Для работы запущены сервер и база данных, браузер имеет доступ к серверу. Выбор СУБД и библиотек остаётся за разработчиком.

<a id="26-apportioning-of-requirements"></a>

### 2.6 Распределение требований

Все требования раздела 3 входят в одну учебную версию. Разработку можно выполнить в три шага: вход и привычки; отметки и серии; очки, значок и ручная проверка. Дополнительные возможности не обязательны для сдачи.

<a id="3-requirements"></a>

## 3. Требования

Ниже приведён минимальный обязательный набор. Сохранены ID соответствующих требований версии 0.1; пропуски в нумерации означают исключённые требования. Для приёмки достаточно ручной демонстрации критериев.

<a id="31-external-interfaces"></a>

### 3.1 Внешние интерфейсы

Взаимодействие пользователя с приложением происходит через браузер.

<a id="311-user-interfaces"></a>

#### 3.1.1 Пользовательские интерфейсы

Достаточно экранов регистрации, входа и главной страницы. На главной странице расположены список привычек, кнопка создания, отметки за сегодня, серии, значки и общая сумма очков. Создание и переименование можно выполнить в простых формах на той же странице.

<a id="312-hardware-interfaces"></a>

#### 3.1.2 Аппаратные интерфейсы

Специальное оборудование не требуется: достаточно компьютера, клавиатуры и мыши.

<a id="313-software-interfaces"></a>

#### 3.1.3 Программные интерфейсы

React-клиент обменивается с Java-сервером данными в формате JSON по HTTP при локальном запуске. Внешние сервисы и интеграции не требуются. При ошибке операции интерфейс показывает понятное сообщение.

<a id="32-functional"></a>

### 3.2 Функциональные требования

Основные действия и игровые правила:

**REQ-FUNC-001 — Регистрация и вход**

- **Требование:** Пользователь должен иметь возможность зарегистрироваться по логину и паролю, войти и выйти.
- **Обоснование:** Личный список привычек.
- **Критерии приёмки:** Новый логин создаёт учётную запись; повторный отклоняется. С верным паролем вход успешен, с неверным показана ошибка. После выхода личный список недоступен. Подтверждение email и восстановление пароля не требуются.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-003 — Создание привычки**

- **Требование:** Пользователь должен иметь возможность создать ежедневную привычку с названием от 1 до 80 символов после удаления пробелов по краям.
- **Обоснование:** Быстро записать желаемое действие.
- **Критерии приёмки:** Привычка появляется в списке. Пустое или слишком длинное название не сохраняется; показано сообщение об ошибке. Описания, категории и настройки расписания не нужны.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-004 — Изменение и удаление привычки**

- **Требование:** Пользователь должен иметь возможность переименовать привычку или удалить её после подтверждения.
- **Обоснование:** Поддерживать список актуальным.
- **Критерии приёмки:** Переименование сохраняет отметки и проверяет название как при создании. Удаление убирает привычку вместе с её отметками; связанные очки и значок больше не учитываются. Отмена подтверждения ничего не меняет. Архив и восстановление не требуются.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-005 — Отметка за сегодня**

- **Требование:** Пользователь должен иметь возможность поставить и снять отметку выполнения за текущую серверную дату.
- **Обоснование:** Ежедневно фиксировать выполнение.
- **Критерии приёмки:** Одна привычка имеет не более одной отметки за дату; повторное сохранение не создаёт дубль. Отмена убирает отметку. Прошлые и будущие даты недоступны для изменения; при смене дня открытый список обновляется при следующем запросе.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-006 — Текущая серия**

- **Требование:** Для каждой привычки система должна показывать число последовательных выполненных дней.
- **Обоснование:** Наглядно показать регулярность.
- **Критерии приёмки:** Если сегодня отмечено, считаются последовательные даты назад от сегодня; иначе — от вчера. Если вчера не отмечено и сегодня ещё не выполнено, серия равна 0. Отмена отметки пересчитывает серию. Лучшую серию хранить и показывать не требуется.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-007 — Очки**

- **Требование:** Система должна показывать общую сумму очков пользователя: 10 за каждую сохранённую отметку его существующих привычек.
- **Обоснование:** Простое игровое поощрение.
- **Критерии приёмки:** Одна отметка даёт 10 очков, две — 20; отмена одной возвращает сумму к 10. Повторный запрос не добавляет очки второй раз. Уровни и отдельная история начислений не требуются.
- **Метод верификации:** ручная проверка.

**REQ-FUNC-008 — Значок за серию**

- **Требование:** Рядом с привычкой должен отображаться значок «7 дней подряд», если её текущая серия не меньше 7.
- **Обоснование:** Небольшая цель для продолжения занятий.
- **Критерии приёмки:** При серии 6 значка нет, при 7 и больше он показан. Если серия становится меньше 7, значок скрывается. Отдельная коллекция наград и постоянное хранение достижений не нужны.
- **Метод верификации:** ручная проверка.

<a id="33-quality-of-service"></a>

### 3.3 Качество обслуживания

Для лабораторной достаточно корректной работы основного сценария на локальном компьютере.

<a id="331-performance"></a>

#### 3.3.1 Производительность

Нагрузочное тестирование, целевые значения p95 и проверка одновременной работы большого числа пользователей не требуются.

<a id="332-security"></a>

#### 3.3.2 Безопасность

Учётные записи должны обеспечивать базовое разделение личных данных.

**REQ-SEC-001 — Защита учётной записи**

- **Требование:** Сервер должен предоставлять доступ только к привычкам и отметкам вошедшего пользователя; пароли должны храниться в виде хешей.
- **Обоснование:** Личные данные пользователей не смешиваются.
- **Критерии приёмки:** Пользователь A не может читать или изменять данные пользователя B, в том числе подставив ID в запрос. Без входа доступ отклоняется. В базе нет паролей в открытом виде; пароли не выводятся в ответы или логи.
- **Метод верификации:** ручная проверка.

<a id="333-reliability"></a>

#### 3.3.3 Надёжность

Результат успешного сохранения должен сохраняться между запусками приложения.

**REQ-REL-001 — Сохранение данных**

- **Требование:** Учётные записи, привычки и отметки должны сохраняться в базе данных.
- **Обоснование:** Прогресс не теряется после завершения работы.
- **Критерии приёмки:** После обновления страницы и перезапуска сервера сохранённые привычки и отметки доступны; сумма очков и серии соответствуют данным. Автоматические резервные копии не требуются.
- **Метод верификации:** ручная проверка.

<a id="334-availability"></a>

#### 3.3.4 Доступность

Приложение доступно во время работы локального сервера. Круглосуточная работа, SLA и мониторинг доступности не требуются.

<a id="335-observability"></a>

#### 3.3.5 Наблюдаемость

Для диагностики достаточно стандартного вывода ошибок сервера в консоль. Отдельная система логирования и сбора метрик не требуется.

<a id="34-compliance"></a>

### 3.4 Соответствие стандартам

Специальные требования по сертификации отсутствуют. Для демонстрации используются тестовые учётные записи.

<a id="35-design-and-implementation"></a>

### 3.5 Проектирование и реализация

При выборе средств реализации приоритет отдаётся простоте учебного проекта.

<a id="351-installation"></a>

#### 3.5.1 Установка

Запуск выполняется локально по инструкции в README.

**REQ-INST-001 — Инструкция запуска**

- **Требование:** README должен содержать необходимые зависимости и команды запуска базы данных, сервера и клиента.
- **Обоснование:** Возможность показать лабораторную работу.
- **Критерии приёмки:** По инструкции удаётся открыть приложение в браузере и выполнить основной сценарий. Сложный установщик не требуется.
- **Метод верификации:** ручная проверка.

<a id="352-build-and-delivery"></a>

#### 3.5.2 Сборка и поставка

Достаточно обычных команд сборки и запуска Java-сервера и React-клиента. CI/CD, контейнеры и автоматическое развёртывание не обязательны.

<a id="353-distribution"></a>

#### 3.5.3 Распределение

Распределённое развёртывание, репликация и несколько серверов не требуются.

<a id="354-maintainability"></a>

#### 3.5.4 Сопровождаемость

Достаточно понятной структуры исходного кода и краткой инструкции запуска. Отдельные эксплуатационные регламенты не требуются.

<a id="355-reusability"></a>

#### 3.5.5 Повторное использование

Создание отдельных библиотек и компонентов для других проектов не требуется.

<a id="356-portability"></a>

#### 3.5.6 Переносимость

Достаточно работы на компьютере разработчика в Chrome. Поддержка других браузеров, мобильная адаптация и отдельное мобильное приложение не обязательны.

<a id="357-cost"></a>

#### 3.5.7 Стоимость

Платные API, подписки и размещение на хостинге для лабораторной не нужны.

<a id="358-deadline"></a>

#### 3.5.8 Сроки

Срок сдачи определяется расписанием лабораторных работ. Отдельный пилот и многонедельное наблюдение за пользователями не требуются.

## 5. Приложения

### 5.1 Пример использования

Пользователь входит в приложение и создаёт привычку «Читать 20 минут». После чтения он ставит отметку за сегодня: серия становится равной 1, сумма очков увеличивается на 10. Через семь дней последовательных выполнений рядом с привычкой появляется значок «7 дней подряд».

### 5.2 Примеры расчёта серии

| История | Результат |
|---|---|
| Вчера и сегодня выполнено | Серия 2 |
| Два предыдущих дня выполнены, сегодня ещё нет | Серия 2 до конца сегодняшнего дня |
| Вчера пропущено, сегодня ещё нет отметки | Серия 0 |
| Вчера пропущено, сегодня выполнено | Новая серия 1 |
| Семь дней подряд выполнено, сегодняшняя отметка отменена | Серия 6, на 10 очков меньше, значок скрыт |
