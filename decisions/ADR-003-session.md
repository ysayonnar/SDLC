# ADR-003 Серверная сессия и проверка владельца

## Контекст и постановка задачи

REQ-FUNC-001 и REQ-SEC-001 требуют входа, выхода, хеширования паролей и разделения данных. REQ-FUNC-009 распространяет изоляцию на CSV. См. VIEW-03/05 в [SDD](../design/ritmo-sdd.md).

## Драйверы решения

Немедленный выход, одна локальная Java-инстанция, отсутствие мобильных и внешних API-клиентов, простая проверка доступа.

## Рассмотренные варианты

Серверная сессия с cookie; JWT в браузере; передача пароля в каждом запросе.

## Итог решения

Серверная сессия, HttpOnly cookie, SameSite=Lax, CSRF-токен для изменяющих запросов и входа, смена session ID при входе. Предполагаемый password encoder — Spring Security Argon2PasswordEncoder с солью и параметрами, зафиксированными при реализации. Хеш не включается в DTO. Выход инвалидирует сессию. user_id берётся только из сессии; чужой ID даёт 404. Реализация не должна зависеть только от скрытой кнопки в UI.

### Последствия

Не требуется отзыв JWT и хранение токена в localStorage. Сессии в памяти теряются при перезапуске: пользователь входит повторно; прогресс в PostgreSQL сохраняется. HTTP допускается только на loopback при локальной демонстрации, для HTTPS cookie должна быть Secure. Один origin через Vite proxy упрощает cookie/CSRF.

### Подтверждение

План AT-01/08/11: выход, неверный пароль, подстановка чужого ID, запрос без CSRF, экспорт чужих данных и проверка логов/БД. Фактических результатов этих испытаний нет.

## Плюсы и минусы вариантов

Сессия: простой отзыв, но серверное состояние. JWT: удобно нескольким API-серверам, но сложнее отзыв и защита хранения. Пароль на каждый запрос: нет сессии, но лишняя передача секрета и неудобный выход; отклонён.

## Дополнительная информация

Пересмотр при нескольких API-серверах или появлении внешних клиентов; параметры хеширования проверяются на целевом компьютере при реализации.
